# CPU PMC 大作业实验结果

实验日期 2026 年 11 月 12 日。PostgreSQL 20devel，GCC 15.2.0，Ubuntu 26.04 / WSL2，AMD Ryzen 9 9950X3D。

## 课程要求对应

已实现源码内的 PMC 模块、连接后端初始化、pmc_name 事件表、课件名称列表参数、Hash 建表观察，以及循环中目标片段的低开销快照差值。GNU make 和 Meson 均能编译。

初始化：执行 sql/init.sql 创建并填充事件表，然后使用课件的 SET halo_watch_pmc_list 或 SET halo_pmc_list 选择事件。示例和初始化 SQL 均保存在同一目录。

## Hash Join 实测

R 表 20000 行，S 表 10000 行，条件为 S.value > 100。三种模式均返回 8990，Hash 建表也处理 8990 个非空键元组。

| 模式 | 目标片段样本 | 分组 read 次数 | RDPMC 快照次数 | 计数器启用时间 ms |
|---|---:|---:|---:|---:|
| 只观察整段 | 0 | 2 | 0 | 1.106 |
| 每元组一对 RDPMC 快照 | 8990 | 2 | 17980 | 1.715 |
| 每元组一对 read 快照 | 8990 | 17982 | 0 | 17.106 |

这三项为演示运行的实际输出，不构成多轮查询耗时基准。完整硬件计数及片段原始计数见 demo_metrics.json，原始 psql 输出见 demo.txt。

整段记录覆盖 MultiExecPrivateHash，包括子计划取元组及建表收尾。片段记录在计算散列和插入表前后取差，排除子计划取元组。采样自身会影响结果，片段计数包含读取路径的部分开销。

## 读取开销对照

固定在逻辑 CPU 0，每轮读取四项活动事件的完整快照 50000 次，重复 7 轮并交替两种方法的先后顺序，采用 CLOCK_MONOTONIC_RAW 计时。

| 方法 | 每次完整快照中位耗时 ns | read 系统调用总次数 |
|---|---:|---:|
| 分组 read 路径 | 845.355 | 350000 |
| mmap RDPMC 路径 | 57.062 | 0 |

本次读取快照的耗时比约为 14.81 倍。该值仅表示此机器上这两条读取路径的开销差异，不是数据库查询整体加速比。

RDPMC 快照的 read 次数为零；测试还在同一线程中验证 RDPMC 前快照 ≤ read 快照 ≤ RDPMC 后快照，检查计数器位宽符号扩展、分组事件 ID 对应及累计计数的区间差分。

## 指标和适用范围

只统计当前线程用户态事件，排除内核与 hypervisor。整段计数按区间 time_enabled/time_running 缩放；不可用事件和没有有效样本的片段输出 null。循环输出为采样片段的原始计数，未自动进行多路复用外推。

L1D 命中率是通用 READ.ACCESS/MISS 事件映射的估算。AMD 派发存储事件包含推测执行，不能称为 Intel 的退休存储指令；初始化表保存 CPU 匹配条件，错误型号会被拒绝。

本次演示关闭并行。默认目标为私有 Hash 建表，没有汇总并行 Hash/worker。WSL 调度、缓存状态、CPU 频率和读取开销都会影响数据，不承诺其他环境复现相同倍数。
